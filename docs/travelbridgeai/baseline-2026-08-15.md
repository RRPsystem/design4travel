## PR 0 CI-strategie (aangepast op baseline)

Uitgangspunt: **bestaande TypeScript/ESLint-config NIET wijzigen of versoepelen.** Alleen `vite build` wordt required (dat is `main`'s huidige de-facto gate via Netlify); typecheck + eslint worden informational zodat counts continu meten of het beter/erger wordt zonder te blokkeren.

### `.github/workflows/ci.yml` (concept — handmatig aan te maken)

```yaml
name: CI

on:
  pull_request:
    branches: [main]
  push:
    branches: [main]

concurrency:
  group: ci-${{ github.ref }}
  cancel-in-progress: true

permissions:
  contents: read

jobs:
  build:
    name: Production build (required)
    runs-on: ubuntu-latest
    timeout-minutes: 15
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'npm'
      - run: npm ci --legacy-peer-deps
      - run: npm run build

  typecheck:
    name: TypeScript (informational)
    runs-on: ubuntu-latest
    timeout-minutes: 10
    continue-on-error: true
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'npm'
      - run: npm ci --legacy-peer-deps
      - run: npx tsc --noEmit -p tsconfig.app.json

  eslint:
    name: ESLint (informational)
    runs-on: ubuntu-latest
    timeout-minutes: 10
    continue-on-error: true
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'npm'
      - run: npm ci --legacy-peer-deps
      - run: npx eslint .
```

Na merge: alleen `Production build (required)` wordt in main branch-protection als required status gezet.

## Design4-generated components check (vóór eerste Design4-PR)

Vereiste per user-instructie: aparte, **strikte** required-check die alleen op Design4-gegenereerde bestanden draait. Moet vóór PR 1 klaarstaan.

### Ontwerp

**Vaste map:** `src/components/design4-generated/**` — alle door Design4 gegenereerde componenten landen hier. Handgeschreven `SECTION_REGISTRY`-imports blijven in `src/components/Site/sections/registry.tsx` en verwijzen naar deze map.

**Aparte `tsconfig.design4.json`** (in TravelBridgeAI-repo, aan te maken bij deze PR):

```jsonc
{
  "extends": "./tsconfig.app.json",
  "include": ["src/components/design4-generated/**/*"],
  "compilerOptions": {
    // erven strict/noUnusedLocals/noUnusedParameters van base
    // eventueel later verscherpen (exactOptionalPropertyTypes, noUncheckedIndexedAccess)
  }
}
```

Waarom aparte tsconfig: losse bestanden aan `tsc` meegeven is niet betrouwbaar (imports over bestandsgrenzen worden niet meegenomen). Een tsconfig met `include` filter is de gestandaardiseerde manier.

### `.github/workflows/design4-check.yml` (concept)

```yaml
name: Design4 component check

on:
  pull_request:
    branches: [main]

concurrency:
  group: design4-check-${{ github.ref }}
  cancel-in-progress: true

permissions:
  contents: read

jobs:
  design4-check:
    name: Design4-generated components (required)
    runs-on: ubuntu-latest
    timeout-minutes: 15
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0

      - uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'npm'

      - name: Detect changes in design4-generated
        id: changes
        run: |
          set -e
          BASE="${{ github.base_ref }}"
          git fetch origin "$BASE" --depth=1
          if git diff --name-only "origin/$BASE...HEAD" -- 'src/components/design4-generated/**' | grep -q .; then
            echo "changed=true" >> "$GITHUB_OUTPUT"
          else
            echo "changed=false" >> "$GITHUB_OUTPUT"
          fi

      - name: No Design4 changes — pass
        if: steps.changes.outputs.changed == 'false'
        run: echo "OK — no Design4-generated components changed in this PR"

      - name: Install dependencies
        if: steps.changes.outputs.changed == 'true'
        run: npm ci --legacy-peer-deps

      - name: Manifest validator (Design4 packages)
        if: steps.changes.outputs.changed == 'true'
        run: node scripts/validate-design4-manifests.mjs
        # script komt mee met de eerste Design4-PR; valideert manifest.json + props.schema.json
        # tegen Design4 SDK-versiecontract

      - name: TypeScript strict check (Design4 files)
        if: steps.changes.outputs.changed == 'true'
        run: npx tsc --noEmit -p tsconfig.design4.json

      - name: ESLint strict check (Design4 files)
        if: steps.changes.outputs.changed == 'true'
        run: npx eslint 'src/components/design4-generated/**/*.{ts,tsx}'

      - name: Vite build (validates registry integration)
        if: steps.changes.outputs.changed == 'true'
        run: npm run build
```

**Gedrag conform user-eis:**
- Altijd rapporteert (job draait altijd, exit 0 zonder Design4-wijzigingen).
- Met wijzigingen: manifest-validator + strict tsc + strict eslint + full vite build (om te bevestigen dat registry-integratie niet breekt).

**Manifest-validator (`scripts/validate-design4-manifests.mjs`)** komt mee met de eerste Design4-generated-component-PR (PR 1). Voor PR 0 zelf hoeven we alleen `ci.yml`, `design4-check.yml` en `tsconfig.design4.json` te toe voegen; de map `src/components/design4-generated/` is nog leeg maar bestaat (met een `.gitkeep`).
